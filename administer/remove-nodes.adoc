= ONTAP 클러스터에서 ASA r2 노드 제거
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
유지 관리, 교체 또는 서비스 종료를 위해 클러스터에서 노드를 제거해야 할 수 있습니다. 노드는 한 번에 하나씩 제거해야 합니다. 노드를 제거하는 경우 해당 노드의 HA 파트너도 함께 제거해야 합니다.



[[step-1-prepare-to-remove-nodes-from-an-asa-r2-cluster]]
== 1단계: ASA r2 클러스터에서 노드를 제거할 준비를 합니다.

ASA r2 클러스터에서 노드를 제거하기 전에 클러스터의 정상 상태를 확인해야 합니다. 그런 다음 해당 노드에서 스토리지 유닛, VLAN 및 LIF를 마이그레이션하거나 삭제하고 스토리지 페일오버를 비활성화해야 합니다.

.단계
. 클러스터가 정상인지 확인하십시오.
+
[source, cli]
----
cluster show
----
. link:../manage-data/move-storage-units.html["이동"] 또는 link:../manage-data/delete-storage-units.html["삭제"] 노드의 모든 스토리지 유닛.
. 제거할 노드에 SCSI 스토리지 장치(LUN)가 있는 경우, link:https://docs.netapp.com/us-en/ontap/san-admin/modify-slm-reporting-nodes-task.html["선택적 LUN 맵(SLM) 보고 노드 목록에서 해당 노드와 해당 HA 파트너를 삭제합니다."^].
+
SLM 보고 노드 목록에서 노드와 해당 HA 파트너를 제거하지 않으면 LUN이 다른 노드로 이동되었더라도 이전에 해당 노드에 있던 LUN에 대한 액세스 권한을 잃을 수 있습니다.

. link:https://docs.netapp.com/us-en/ontap/networking/delete_a_lif.html["삭제"^] 또는 link:https://docs.netapp.com/us-en/ontap/san-admin/move-san-lifs-task.html["마이그레이션"^] 노드의 모든 네트워크 인터페이스(LIF).
+
** 데이터 LIF는 다른 노드로 이동하거나 삭제해야 합니다.
+
iSCSI LIF 마이그레이션은 홈 노드 또는 HA 파트너의 포트로만 제한되므로 해당 LIF를 삭제해야 합니다.

** 클러스터 간 LIF는 삭제해야 합니다.
+
클러스터 간 LIF를 삭제하면 무시해도 되는 경고 메시지가 표시됩니다.

** 클러스터 관리 LIF를 다른 노드로 옮겨야 합니다.


. link:../administer/manage-cluster-networking.html#delete-a-vlan["모든 VLAN 삭제"] 노드에서.
. 해당 노드의 스토리지 페일오버를 비활성화합니다.
+
[source, cli]
----
storage failover modify -enabled false -node <nodename>
----


.다음 단계
HA 쌍의 첫 번째 노드를 클러스터에서 제거한 다음 해당 HA 파트너 노드를 제거합니다.



[[step-2-remove-a-node-from-an-asa-r2-cluster]]
== 2단계: ASA r2 클러스터에서 노드 제거

ASA r2 클러스터에서 노드를 제거하려면 먼저 노드 제거 준비 단계를 완료해야 합니다. 클러스터에서 노드를 제거한 후에는 해당 노드의 HA 파트너도 제거해야 합니다.

.시작하기 전에
link:../get-help/manage-autosupport.html#send-autosupport-data["AutoSupport 메시지를 발행합니다"]하여 클러스터에서 노드를 제거하고 있음을 NetApp 기술 지원에 알리는 것이 좋습니다.


NOTE: 자동 ONTAP 업그레이드가 진행 중일 때는 클러스터에서 노드를 제거하거나 노드의 이름을 변경하지 마십시오.

.이 작업에 대해
* 4노드 클러스터에서 2개의 노드를 제거하면 나머지 2개의 노드에서 클러스터 HA가 자동으로 설정됩니다.
* 클러스터에서 노드를 제거하기 전에 해당 노드에 연결된 모든 디스크의 모든 시스템 및 사용자 데이터에 대한 접근을 차단해야 합니다.
* 클러스터에서 노드가 잘못 제거된 경우 복구 옵션에 대한 지원을 받으려면 NetApp 지원 팀에 문의하십시오.


.단계
. 권한 수준을 고급으로 변경합니다.
+
[source, cli]
----
set -privilege advanced
----
. 클러스터에서 엡실론 값을 보유한 노드를 식별하십시오.
+
[source, cli]
----
cluster show
----
+
다음 예에서 "node0"은 현재 epsilon을 보유하고 있습니다.

+
[listing]
----
cluster::*> cluster show
Node                 Health  Eligibility  Epsilon
-------------------- ------- ------------ ------------
node0                true    true         true
node1                true    true         false
node2                true    true         false
node3                true    true         false
----
. 제거하려는 노드에 엡실론이 있는 경우, 엡실론을 남아 있는 노드로 옮기십시오.
+
.. 노드에서 엡실론을 제거합니다.
+
[source, cli]
----
cluster modify -node <name_of_node_to_be_removed> -epsilon false
----
.. 엡실론을 다른 노드로 이동합니다.
+
[source, cli]
----
cluster modify -node <node_name> -epsilon true
----


. 현재 기본 노드를 식별하십시오.
+
[source, cli]
----
cluster ring show
----
+
기본 노드는 mgmt, vldb, vifmgr, bcomd, crs 등의 프로세스를 보유하는 노드입니다.

. 제거하려는 노드가 현재 기본 노드인 경우, 클러스터의 다른 노드가 기본 노드로 선출될 수 있도록 설정하십시오.
+
.. 현재 기본 노드가 클러스터에 참여할 수 없도록 설정합니다.
+
[source, cli]
----
cluster modify -node <node_name> -eligibility false
----
+
기본 노드가 더 이상 사용 가능하지 않게 되면 클러스터 쿼럼에 의해 나머지 노드 중 하나가 새로운 기본 노드로 선출됩니다. HA 쌍에서 첫 번째 노드에 이 단계를 수행하는 경우 해당 노드만 사용 가능하지 않음으로 표시하십시오. 파트너 노드에 대해 이 단계를 반복하기 전까지는 파트너 노드의 상태를 변경하지 마십시오.

+
파트너 노드가 새로운 기본 노드로 선출되고 엡실론을 보유한 경우, 파트너 노드를 부적격으로 표시하기 전에 엡실론을 다른 노드로 이동해야 합니다.

.. 이전 기본 노드가 클러스터에 다시 참여할 수 있도록 자격을 부여합니다.
+
[source, cli]
----
cluster modify -node <node_name> -eligibility true
----


. 클러스터에서 제거하지 않을 노드의 원격 노드 관리 LIF 또는 클러스터 관리 LIF에 로그인하십시오.
. 노드 이름 또는 노드 IP 주소를 사용하여 클러스터에서 노드를 제거하십시오.
+
여러 버전이 혼합된 클러스터에서 마지막으로 남은 하위 버전 노드를 제거하는 경우, 다음 명령과 함께 -skip-last-low-version-node-check 매개변수를 사용하십시오.

+
** 노드 이름을 사용하여 노드를 제거합니다.
+
[source, cli]
----
cluster remove-node -node <node_name>
----
** 노드 IP 주소를 사용하여 노드를 제거합니다.
+
[source, cli]
----
cluster remove-node -cluster_ip <node_ip>
----
+
노드를 제거하기 전에 해결해야 할 조건이 있는 경우 오류 메시지가 생성됩니다. 이 경우 조건을 해결한 후  `cluster remove-node` 명령을 다시 실행하십시오.

+
노드는 클러스터에서 성공적으로 제거된 후 자동으로 재부팅됩니다.





.다음 단계
장애 조치 파트너를 클러스터에서 제거하려면 이 단계를 반복하십시오.

.관련 정보
link:https://docs.netapp.com/us-en/ontap-cli/cluster-remove-node.html["cluster remove-node"] 명령에 대해 자세히 알아보십시오.



[[step-3-optionally-erase-the-node-configuration-and-initialize-all-disks]]
== 3단계: 선택적으로 노드 구성을 지우고 모든 디스크를 초기화합니다.

ASA r2 클러스터에서 제거한 노드를 다른 용도로 사용하려면 해당 노드의 구성을 지우고 모든 디스크를 초기화해야 클러스터에 다시 참여할 수 있습니다.

.단계
. 부팅 과정 중 메시지가 나타나면 *Ctrl-C* 를 눌러 부팅 메뉴를 표시합니다.
. 부팅 메뉴 옵션 *(4) Clean configuration and initialize all disks* 또는 옵션 *(9) Configure Advanced Drive Partitioning*을 선택하여 노드의 구성을 지우고 모든 디스크를 초기화합니다.
