= ASA r2 클러스터에서 ASA 또는 AFF 클러스터로 스토리지 VM 마이그레이션
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ONTAP 9.20.1부터 2노드 ASA r2 클러스터에서 2노드 ASA 또는 2노드 AFF 클러스터로 스토리지 가상 머신(VM)을 중단 없이 마이그레이션할 수 있습니다. SAN 및 NAS 워크로드를 통합하거나, ASA r2 시스템에서 사용할 수 없는 ONTAP 기능을 도입하거나, 하드웨어를 교체하기 위해 스토리지 VM을 마이그레이션해야 할 수 있습니다. 마이그레이션 중에 기존 호스트 매핑과 LUN 및 네임스페이스에 대한 스토리지 유닛 구성이 유지되므로 운영 노력과 위험이 줄어듭니다.

.시작하기 전에
* 클러스터 관리자여야 합니다.
* 두 클러스터의 모든 노드는 ONTAP 9.20.1 이상 버전을 실행해야 합니다.


.이 작업에 대해
* ASA r2 스토리지 VM은 2노드 ASA r2 클러스터에서 2노드 AFF 클러스터로만 마이그레이션할 수 있습니다.
+
** ASA r2 스토리지 VM은 FAS 클러스터 또는 노드가 2개보다 많은 ASA 또는 AFF 클러스터로 마이그레이션할 수 없습니다.
** 노드가 두 개를 초과하는 ASA r2 클러스터에서는 ASA r2 스토리지 VM을 마이그레이션할 수 없습니다.


* ASA r2 클러스터에서 AFF 클러스터로의 데이터 마이그레이션은 되돌릴 수 없습니다.
+
전환 전에 마이그레이션을 중단할 수 있지만, 전환이 시작된 후에는 마이그레이션을 중단하거나 되돌릴 수 없습니다. 마이그레이션이 완료된 후에는 AFF 클러스터에서 ASA r2 클러스터로 데이터를 마이그레이션할 수 없습니다.

+
link:migrate-svm.html["ASA에서 ASA r2 클러스터로 스토리지 VM 마이그레이션"]할 수 있습니다.

* 한 번에 하나의 스토리지 VM만 마이그레이션할 수 있습니다.
* 스토리지 VM은 최대 400개의 스토리지 유닛을 포함할 수 있습니다.
* 스토리지 VM에는 SnapMirror 타겟 스토리지 장치가 포함될 수 없습니다.




[[step-1-create-a-cluster-peer-relationship]]
== 1단계: 클러스터 피어 관계를 생성합니다

ASA r2 클러스터에서 스토리지 VM을 마이그레이션하기 전에 피어 관계를 생성해야 합니다. 피어 관계는 ONTAP 클러스터와 스토리지 VM이 안전하게 데이터를 교환할 수 있도록 네트워크 연결을 정의합니다.

.이 작업에 대해
다음 절차에서 ASA 또는 AFF 클러스터는 _타겟_ 클러스터이고 ASA r2 클러스터는 _소스_ 클러스터입니다.

.시작하기 전에
다음 방법 중 하나를 사용하여 피어링 중인 클러스터의 모든 노드에 클러스터 간 LIF를 생성해야 합니다.

* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-share-data-ports-task.html["공유 데이터 포트에서 클러스터 간 LIF 구성"^]
* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-use-dedicated-ports-task.html["전용 데이터 포트에 클러스터 간 LIF 구성"^]
* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-use-ports-own-networks-task.html["사용자 정의 IP 공간에서 클러스터 간 LIF 구성"^]


.단계
. 타겟 클러스터에서 소스 클러스터와 피어 관계를 생성하고 암호를 생성합니다:
+
[source, cli]
----
cluster peer create -peer-addrs <source_cluster_LIF_IPs> -generate-passphrase
----
+
다음 예제에서는 클러스터 1과 클러스터 2 사이에 클러스터 피어 관계를 만들고 시스템에서 생성한 암호를 만듭니다.

+
[listing]
----
cluster1::> cluster peer create -peer-addrs 10.98.191.193 -generate-passphrase
Passphrase: UCa+6lRVICXeL/gq1WrK7ShR
            Peer Cluster Name: cluster2
            Initial Allowed Vserver Peers: -
            Expiration Time: 6/7/2017 09:16:10 +5:30
            Intercluster LIF IP: 10.140.106.185
Warning: make a note of the passphrase - it cannot be displayed again.

----
. 생성된 암호를 복사합니다.
. 소스 클러스터에서 타겟 클러스터와 피어 관계를 생성합니다:
+
[source, cli]
----
cluster peer create -peer-addrs <destination_cluster_LIF_IPs>
----
. 타겟 클러스터에서 생성된 암호를 입력합니다.
. 클러스터 피어 관계가 생성되었는지 확인하세요.
+
[source, cli]
----
cluster peer show
----
+
다음 예에서는 피어링에 성공한 클러스터에 대한 예상 출력을 표시합니다.

+
[listing]
----
cluster1::> cluster peer show

Peer Cluster Name   Cluster Serial Number   Availability   Authentication
-----------------   ---------------------   -------------- --------------
cluster2             1-80-123456             Available      ok
----


.결과
클러스터가 피어링됩니다. 스토리지 VM 데이터를 안전하게 전송할 수 있습니다.

.다음 단계
이제 ASA r2 스토리지 VM을 마이그레이션할 준비가 되었습니다.



[[step-2-prepare-the-asa-r2-storage-vm-for-migration]]
== 2단계: 마이그레이션을 위해 ASA r2 스토리지 VM을 준비합니다

ASA r2 클러스터에서 스토리지 가상 머신(VM)을 마이그레이션하기 전에 복제 및 SnapMirror 활성 동기화 관계를 제거하고 다양한 검사를 수행해야 합니다.

.단계
. link:../data-protection/snapmirror-active-sync-break-relationship.html["기존 복제 관계를 모두 제거합니다"].
. link:../data-protection/snapmirror-active-sync-delete-relationship.html["기존 SnapMirror 활성 동기화 관계를 모두 제거하십시오"].
. IPsec이 활성화되어 있는지 확인하십시오:
+
[source, cli]
----
security ipsec config show
----
+
.. IPsec이 활성화되어 있으면 비활성화하십시오:
+
[source, cli]
----
security ipsec config modify -is-enabled -false
----
+
link:https://docs.netapp.com/us-en/ontap-cli/security-ipsec-config-show.html["security ipsec config show"^] 명령에 대해 자세히 알아보십시오.

.. IPv6 및 가상 IP(VIP) LIF를 확인하십시오:
+
[source, cli]
----
network interface show -vserver <storage_vm_name> -fields address-family, is-vip
----
+
IPv6 LIF의 경우  `-address-family`은(는)  `ipv6`입니다. VIP LIF의 경우  `-is-vip` 매개변수는  `true`입니다.

.. IPv6 또는 VIP LIF가 있는 경우 제거하십시오:
+
[source, cli]
----
network interface delete -vserver <storage_vm_name> - lif <lif_name>
----
.. 스토리지 VM에 IPv6 또는 VIP LIF가 남아 있지 않은지 확인하십시오:
+
[source, cli]
----
network interface show -vserver <storage_VM_name>
----
+
link:https://docs.netapp.com/us-en/ontap-cli/network-interface-show.html["네트워크 인터페이스 show"^] 및 link:https://docs.netapp.com/us-en/ontap-cli/network-interface-delete.html["network interface delete"^] 명령에 대해 자세히 알아보십시오.



. 인터페이스 그룹이 구성되어 있는지 확인하십시오:
+
[source, cli]
----
network port ifgrp show
----
+
.. 인터페이스 그룹이 구성된 경우 스토리지 VM의 LIF가 인터페이스 그룹에 바인딩되어 있는지 확인합니다:
+
[source, cli]
----
network interface show -vserver <storage_VM_name> -fields home,node, home-port, curr-node, curr-port
----
.. 스토리지 VM의 LIF가 인터페이스 그룹에 바인딩된 경우, 해당 LIF를 다른 물리적 포트로 마이그레이션하십시오:
+
[source, cli]
----
network interface migrate -vserver <storage_VM_name> -lif <LIF> -des-node <destination_node> -dest-port <destination_port>
----
+
link:https://docs.netapp.com/us-en/ontap-cli/network-port-ifgrp-show.html["network port ifgrp show"^] 명령에 대해 자세히 알아보십시오.





.다음 단계
이제 마이그레이션 사전 검사를 실행할 준비가 되었습니다.



[[step-3-execute-the-migration-pre-check]]
== 3단계: 마이그레이션 사전 검사 실행

ASA r2 클러스터에서 스토리지 VM을 마이그레이션하기 전에 마이그레이션 사전 검사를 실행하고 필요한 문제를 해결해야 합니다. 사전 검사가 성공적으로 통과될 때까지 마이그레이션을 수행할 수 없습니다.

.단계
. 타겟 클러스터에서 마이그레이션 사전 검사를 실행하십시오:
+
[source, cli]
----
vserver migrate start -vserver <storage_VM> -source-cluster <sourcecluster> -check-only true
----
+
마이그레이션을 준비하기 위해 해결해야 할 문제가 있는 경우, 문제와 해결 조치가 표시됩니다. 문제를 해결하고 사전 점검이 성공적으로 완료될 때까지 반복하십시오.



.다음 단계
이제 ASA r2 클러스터에서 스토리지 VM을 마이그레이션할 준비가 되었습니다.



[[step-4-migrate-a-storage-vm-from-an-asa-r2-cluster]]
== 4단계: ASA r2 클러스터에서 스토리지 VM 마이그레이션

ASA r2와 ASA 또는 AFF 클러스터 간에 필요한 클러스터 피어 관계를 생성하고 두 클러스터를 준비하는 단계를 완료한 후에는 스토리지 VM 마이그레이션을 시작할 수 있습니다.

모범 사례로, 마이그레이션 워크로드가 실행될 수 있도록 ASA r2 클러스터와 AFF 클러스터 모두에 30%의 CPU 여유 공간을 남겨 두십시오.

.이 작업에 대해
* 스토리지 VM 마이그레이션 후 클라이언트 I/O는 중단 없이 타겟 클러스터로 원활하게 전환되며, ASA r2 클러스터의 스토리지 VM은 자동으로 제거됩니다. 자동 전환 및 자동 스토리지 VM 제거는 기본적으로 활성화되어 있습니다. 필요에 따라 두 옵션 중 하나 또는 둘 다를 비활성화하고 수동으로 수행할 수 있습니다.
* ASA 클러스터는 스토리지 VM을 마이그레이션할 _소스_ 클러스터이고, ASA r2 클러스터는 스토리지 VM을 마이그레이션할 _타겟_ 클러스터입니다.


.단계
. 타겟 클러스터에서 스토리지 VM 마이그레이션을 시작합니다:
+
[source, cli]
----
vserver migrate start -vserver <storage_VM_name> -source-cluster <source_cluster>
----
+
자동 전환을 비활성화하려면  `-auto-cutover false` 매개변수를 사용하십시오. 소스 스토리지 VM의 자동 제거를 비활성화하려면  `-auto-source-cleanup false` 매개변수를 사용하십시오.

. 마이그레이션 상태 모니터링
+
[source, cli]
----
vserver migrate show -vserver <storage_VM_name>
----
+
자동 전환이 시작되기 전에 마이그레이션을 일시 중지하거나 취소해야 하는 경우 다음을 사용하세요. `vserver migrate pause` 그리고 `vserver migrate abort` 명령.  취소하기 전에 마이그레이션을 일시 중지해야 합니다.  전환이 시작된 후에는 마이그레이션을 취소할 수 없습니다.

+
자동 전환이 활성화된 경우, 마이그레이션이 완료되면 *상태*가 *migration-complete*로 표시됩니다. 자동 전환이 비활성화된 경우, *상태*가 *Ready for source cleanup*으로 표시됩니다.



.결과
스토리지 VM이 ASA r2 클러스터에서 타겟 클러스터로 마이그레이션됩니다.

.다음 단계
자동 전환 및 자동 스토리지 VM 제거 기능을 비활성화한 경우, 마이그레이션 후 전환 및 정리 작업을 수행하여 ASA r2 클라이언트를 타겟 클러스터로 수동으로 전환하고 ASA r2 클러스터에서 스토리지 VM을 제거하십시오.



[[step-5-post-migration-cutover-and-cleanup]]
== 5단계: 마이그레이션 후 전환 및 정리

클러스터 간 스토리지 VM 마이그레이션 중에 클라이언트 I/O는 타겟 클러스터로 전환되고 소스 클러스터의 스토리지 VM은 자동으로 제거됩니다. 마이그레이션 중에 소스 스토리지 VM의 자동 전환 및 제거를 비활성화하도록 선택한 경우, 마이그레이션 상태가 *소스 정리 준비됨*에 도달한 후 이러한 단계를 수동으로 수행해야 합니다.



[[manually-cut-over-clients-after-a-storage-vm-migration]]
=== 스토리지 VM 마이그레이션 후 클라이언트를 수동으로 전환

스토리지 VM의 클러스터 간 마이그레이션 중에 자동 클라이언트 전환을 비활성화한 경우, 마이그레이션 관계가 전환 준비가 완료되면 수동으로 전환을 수행하여 대상 스토리지 VM이 클라이언트에 데이터를 제공할 수 있도록 해야 합니다.

.이 작업에 대해
타겟 클러스터에서 이 작업을 수행하십시오.

.단계
. 클라이언트 전환을 수동으로 실행합니다:
+
[source, cli]
----
vserver migrate cutover -vserver <storage_VM_name>
----
. 컷오버 작업이 완료되었는지 확인하세요.
+
[source, cli]
----
vserver migrate show
----


.결과
타겟 클러스터의 스토리지 VM에서 클라이언트로 데이터가 제공되고 있습니다.

.다음 단계
이제 소스 클러스터에서 스토리지 VM을 제거할 준비가 되었습니다.



[[manually-remove-a-storage-vm-after-migration]]
=== 마이그레이션 후 스토리지 VM을 수동으로 제거

클러스터 간 스토리지 VM 마이그레이션 중에 자동 소스 정리를 비활성화한 경우, 마이그레이션이 완료된 후 스토리지 공간을 확보하기 위해 소스 클러스터에서 스토리지 VM을 제거하십시오.

.시작하기 전에
클라이언트는 타겟 클러스터에서 데이터를 제공해야 합니다.

.단계
. 소스 클러스터에서 소스 스토리지 VM의 상태가 *소스 정리 준비됨*인지 확인합니다:
+
[source, cli]
----
vserver migrate show
----
. 소스 스토리지 VM을 제거합니다:
+
[source, cli]
----
vserver migrate source-cleanup -vserver <storage_VM_name>
----


.결과
소스 클러스터의 스토리지 VM이 제거되었습니다.
